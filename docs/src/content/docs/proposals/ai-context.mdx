**The question it answers: how did machines make this page — and how may
they use it?** Two production fields (`generated-by`, `provenance`) and two
consumption fields (`risks`, `sample-questions`).

## Fields

| Field | Type | Notes |
|---|---|---|
| `generated-by` | string, non-empty | The model, agent, or tool that generated the page's content |
| `provenance` | list of entries | Per-model attribution of machine-proposed *metadata*: which fields, at what confidence |
| `risks` | string or list | Pre-flight flags for agents and reviewers — open enum, seven recommended values |
| `sample-questions` | string or list | Questions this page should answer — the retrieval-eval hook |

A provenance entry: `generated-by` (required), `fields` (which frontmatter
keys it proposed — non-empty, unique), `confidence` (per-field, 0..1).

## Example

```yaml
---
title: Install the operator on Kubernetes
description: Deploy the operator with Helm and verify the rollout.
generated-by: claude-fable-5
provenance:
  - generated-by: claude-fable-5
    fields: [intent, sample-questions]
    confidence: { intent: 0.9, sample-questions: 0.84 }
risks: [privileged, cost-incurring]
sample-questions:
  - How do I install the operator on EKS?
  - Which Helm values enable the webhook?
---
```

## Design decisions

- **Machines propose; humans retire the provenance.** A provenance entry
  is the human-review trail for machine-filled metadata: a human deletes
  the entry once its fields are reviewed, so *a surviving entry means
  unreviewed machine metadata*. The same pattern appears in the
  [kg](/docmeta/proposals/kg/) block and both
  [eval](/docmeta/proposals/evals/) vocabularies — one family-wide answer
  to "which of this metadata did a machine write, and has anyone
  checked?"
- **`generated-by` attributes the content; `provenance` attributes the
  metadata.** Different facts. Consumers also use `generated-by` for
  self-preference-bias checks: a judge should know when it is grading its
  own author.
- **`risks` is the open-enum idiom.** Seven recommended flags —
  `cost-incurring`, `destructive`, `irreversible`, `privileged` (the
  operational four), `open-world`, `read-only`, `idempotent` (mirroring
  MCP's tool annotations, the published prior art for agent-facing
  hints) — and any non-empty string stays legal. An unannotated page is
  *unassessed*, not safe, which is why the assurances are worth stating;
  and a consumer switching on a flag should treat unknown values as
  caution, not absence.
- **`sample-questions` closes the retrieval loop.** Ask them against the
  corpus and measure whether this page carries the answer. Assertion-style
  per-page evals belong to the [evals vocabulary](/docmeta/proposals/evals/),
  not here.

## What reviewers should poke at

Whether `generated-by` and `provenance` belong here or in
[core](/docmeta/proposals/core/) — the eval bias check and the kg harvest
both read `generated-by`, which argues for the one vocabulary that is
always present. Also whether `risks` is the right name for a field that
carries assurances (`read-only`) alongside cautions.
