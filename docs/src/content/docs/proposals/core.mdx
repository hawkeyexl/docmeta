**The question it answers: what is this page?** Core is the minimum
every page meets: a title and a sentence. It works in any repo, with no
content strategy, no review process, and no tooling. The whole family is
intended for docmeta's default set, and core is the only part of it that
requires anything.

## Fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `title` | string, non-empty | **yes** | A single non-empty string. An array is rejected |
| `description` | string, non-empty | **yes** | One full sentence. It becomes the search snippet and is the first thing retrieval reads |
| `id` | string, non-empty | no | A stable identifier that does not change when the file moves. `related-pages`, `prerequisites`, and `replaced-by` point at it |
| `type` | string, non-empty | no | What kind of content this is. Taxonomy schemas (Diátaxis, TGDP) narrow it; `kg.type` holds the same fact in iiRDS terms |
| `keywords` | string or list of non-empty strings | no | Search words. A comma-separated string is the AsciiDoc form Antora reads |
| `language` | string, non-empty | no | The page's natural language as one BCP 47 tag, region and script subtags included (`pt-BR`, `zh-Hant-TW`). Recommended, not enforced. This is the locale field |
| `docmeta-vocabularies` | map of family name to version string | no | Which version of each docmeta vocabulary this file is written against, such as `evals: 1.0.0-proposal.2`. At least one entry. Absent means the version the reading tool implements |

## Examples

The minimum:

```yaml
---
title: Install the operator on Kubernetes
description: Deploy the operator with Helm and verify the rollout.
---
```

Everything core knows about:

```yaml
---
title: Install the operator on Kubernetes
description: Deploy the operator with Helm and verify the rollout.
id: install-operator-k8s
type: how-to
keywords: [helm, operator, kubernetes]
language: en
docmeta-vocabularies:
  evals: 1.0.0-proposal.2
---
```

## Design decisions

- **Every string is non-empty, and four fields take one value.** `title`,
  `description`, `type`, and `language` are single strings, and no string
  core defines may be empty. This is stricter than the loosest schemas
  that share these keys: Docusaurus permits an empty title, and Dublin
  Core allows repeated elements. These are the only exceptions to the
  family's compatibility rule, under which a document valid under another
  built-in schema stays valid here. The automated compatibility check
  records each exception as an expected rejection, so an exception that is
  not on this list fails CI.
- **Core describes content, never rendering.** There is no `slug`,
  `layout`, `image`, or `tags` here. Rendering keys stay with your
  generator. Core describes what the page is.
- **`language` is the locale field, and there is no `locale` key.** A BCP 47
  tag already carries region and script, so `pt-BR` says everything a
  page-level locale can. What a locale means beyond the tag is rendering:
  date formats, collation, text direction, and which site tree a page
  renders in. The W3C draws the same line: a language tag identifies
  content, and a locale identifies a reader's preferences. Starlight does
  too. It keys locales by directory and names the content tag `lang`.
  Calling the key `locale` would also invite the `en_US` spelling that
  Open Graph uses and BCP 47 does not.
- **Derivable facts stay out.** There is no creation `date` and no
  `updated` stamp. Git already knows both, and a hand-typed copy goes
  stale without anyone noticing.
- **People are in stewardship.** `authors` was a core field until review
  round 6. It now sits with `owner`, `stakeholders`, and `reviewed-by` in
  the [stewardship vocabulary](/docmeta/proposals/stewardship/). Core
  answers what the page is. Who wrote it belongs with the question of
  whether the page is cared for. Moving it makes attribution one adoption
  decision together with the other people fields, instead of a seventh
  field in the minimum every page meets.
- **`docmeta-vocabularies` says which versions a file targets.** A
  vocabulary that reserves a key prefix, as [evals](/docmeta/proposals/evals/)
  reserves `eval-`, has to choose between rejecting future keys and
  catching present typos. That is the case that prompted this key. With
  the declaration present, a tool checks the version first: a major above
  what it implements is a distinct error naming both versions, and only
  then does unknown-key rejection run, so a key from a newer vocabulary is
  never reported as a typo. Absent, the file targets whatever version the
  tool implements, which stays the common case. The key lives in core
  because every family shares the gap. Artifacts nest it as
  `metadata.docmeta-vocabularies`, the way
  [artifact-evals](/docmeta/proposals/artifact-evals/) nests the rest of its
  keys. An empty map is rejected, matching the rule that every list in the
  family has at least one entry.

## What reviewers should poke at

Three questions. Is requiring `title` and `description` on unconfigured
runs the right default? Is the non-empty rule worth the recorded
exception against Docusaurus's documented tolerance for empty titles? And
does moving `authors` to stewardship match where you would look for it?
Docusaurus and MyST both keep it next to `title`, so this is the one place
the family reads differently from the generators it composes with.
